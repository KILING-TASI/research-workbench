# 独立历史、财务与公告采集

统一入口 research_pipeline.py collect 或 collect-batch；Python标准库，无项目缓存依赖。stock/etf按代码推定沪深市场，债券必须明确market：0深市、1沪市。该选择不是官方品种核验；银行间债券尚不支持。

collect参数：--kind stock|etf|bond|convertible|government-bond|credit-bond --codes 六位代码 --start YYYY-MM-DD --as-of YYYY-MM-DD --refresh --market 0|1。基金沿用净值采集。

历史按年度窗口取东方财富未复权日线，失败尝试腾讯未复权日线。返回区间首尾与记录不证明上市以来完整；无交易与数据缺失未能自动区分。原始价格不含分红、票息，不可直接用于总收益比较。腾讯成交量单位未核验，不能用于金额换算。

股票财务获取东方财富财务主要指标摘要，分页保留原字段，按报告期及NOTICE_DATE过滤，不等于完整三张报表或原文核验。公告分页获取元数据，校验证券代码；附件URL仅保留接口明确返回值，不猜PDF。空公告标为覆盖未确认。ETF基金报告、债券发行人财务映射仍缺。

批量JSON示例：
```json
{"asOf":"2026-10-03","refresh":true,"jobId":"research-001","resume":false,"retries":2,"requests":[{"kind":"stock","code":"600036","start":"2025-01-01"},{"kind":"convertible","code":"113052","market":"1","start":"2025-01-01"}]}
```

1至1000项；每项明确品种/代码，可设start和market。retries为0至3，只重试超时、断连、502/503/504，拒绝访问与结构错误不重试。逐标的原子保存到用户目录research-data/batches/jobId.json；中断后相同请求加resume:true续采，成功项跳过，失败及部分成功项重跑。参数变更须用新jobId；不支持同job并发执行。

每项输出attempts、collectionStatus、组件状态、错误、来源及原抓取时间；区分available/cached/partial/cached-after-failure/unavailable。组件缓存按代码、市场、区间隔离；刷新失败不覆盖旧成功数据。尚无跨区间增量合并，区间变化会重新取数；断点功能不等于自动定时更新。

resume必须为布尔值。拒绝访问、权限不足和限流信息优先于超时线索，不立即重复请求。损坏或结构不完整的缓存列为资料缺口；刷新成功才替换，刷新失败不会将损坏缓存当作有效数据。缓存保留原抓取时间，不把本次读取时间当作数据更新时间。

续采跳过成功条目前核对保存内容摘要；旧断点缺少摘要或条目内容发生变化时重新采集，并列出原因。断点文件整体不可读时保留原文件并提示使用新jobId。摘要不是数据真实性核验，也不是数据新鲜度证明；刷新新数据应使用新的批次标识。

整批请求在取数前检查起始日期、截止日期和市场参数；债券须明确沪深市场。任何一项无效时先纠正参数，避免批次中途才发现输入问题。此检查不等于证券身份原文核验。

独立基金净值取数不静默删除非法净值；接口出现无效观测时明确失败并保留原有效缓存。缓存证券身份、日期序列与净值结构不一致时不可复用。日期输入采用YYYY-MM-DD，不能使用紧凑日期格式。普通现金分红可解析不等于分红原文核验；拆分或其他事件口径不明时，基础收益比较停止计算，并在资料说明中列出。

基金批量请求可指定start，返回历史按start至asOf过滤，底层缓存仍保留实际抓取的历史；请求窗口无观测时不标为成功。续采必须存在对应断点，不能用resume隐式新建批次。Windows保留设备名称不能用作jobId；同一股票或ETF的默认市场和相同显式市场视为重复请求。

缓存抓取时间须带时区；基金口径、名称身份和报价日期价格参与有效性检查。行情缓存核对价格、高低价及请求区间，结构异常不能作为旧成功资料回退。组件使用独立临时文件完成替换；这不代表支持同一jobId并发续采。

## 财务窗口与刷新失败
股票批量请求可增加 `financialStart: "2025-01-01"`，独立于行情 start，且不得晚于 asOf。财务摘要不等于完整三表或公告原文核验。新数据先核对日期、数值、标的及来源链接，再保存；校验或写入失败时保留旧缓存及其原始时间。来源链接格式通过不代表来源真实性通过。

## 元数据一致性
公告标识不得为空白；财务记录要求报告期和披露日期有效，同一报告期与披露日的重复记录阻止提交。不同披露日的修订记录不据此去重。来源须为无凭据 HTTPS 链接，空白、控制字符与无效端口拒绝接收。上述检查只核对结构与口径，不证明第三方数值和原文一致。

## 断点方法与比较区间
断点登记采集和校验程序的文件摘要。方法变更或旧断点缺少方法记录时，保留原断点并提示改用新jobId重新采集，不直接复用旧成功状态。文件摘要仅用于识别程序变化，不证明来源真实性。

结果保留请求区间与实际观测区间。资料说明按实际日期交集列示可对齐区间；无法对齐时不开展直接排名。相同日期不代表分红、复权、币种或基准一致。实际首尾未覆盖请求边界时提示差异，不据此认定缺少交易日，也不补零或插值。

## 历史行情名称留存
历史源返回名称时，随代码、来源及抓取时间保留，并在缓存回退中沿用原记录。跨年度窗口名称不一致时拒绝静默拼接，需确认是否更名或对象不一致。第三方代码名称匹配不等于正式发行或基金合同身份核验；来源未提供名称时继续留空。

## 组件缓存内容校验
新保存的行情、财务摘要与公告组件登记内容摘要，覆盖数据、来源、请求、抓取时间及名称身份。读取时摘要缺失或不一致不复用旧资料，原文件保留；只有新取数通过校验并保存后才替换。旧版本未登记摘要的缓存需主动刷新。摘要用于识别保存后内容变化，不认证来源真实性，也不能防止内容与摘要被同时修改。

## ETF公告目录
ETF采用基金公告目录，股票沿用股票公告目录。逐条检查基金代码、公告ID、标题和日期，分页重复或日期乱序拒绝提交，超过上限不交付截断结果。缓存请求登记目录类型，不能把旧股票接口缓存当作基金目录结果。空结果仍标记覆盖未确认。目录仅提供元数据；未返回附件时留空，可按明确公告ID调用文档归档入口，不能猜PDF链接或宣称正文核验完成。
