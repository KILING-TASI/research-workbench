# 公司池财报研究流程

输入公司代码、自然年报告期和披露截止日，串联三表、报告覆盖、原文页码、季度分析、公司与样本点评、Excel底稿。默认按用户请求运行，没有后台刷新；指定池不等于全行业。

## 一次运行

```text
python scripts/financial_research_pipeline.py INPUT.json --out-dir NEW_DIRECTORY
```

```json
{"period":"2026-06-30","asOf":"2026-10-05","companies":[
 {"code":"300308","metadata":{"name":"中际旭创","group":"光通信指定池","classificationVersion":"用户分组v1","sectorType":"general","scope":"consolidated","currency":"CNY","unit":"渠道原单位（待原文确认）"}}
]}
```

AI从提问组织参数。金融/普通企业、报表范围、币种、单位与分组版本需明确；声明不是原文确认。支持1至20家公司。三表读取目标年前两年起数据，覆盖差分及比较期所需窗口；缺期仍不补造。

## 分步入口

1. `python scripts/company_report_batch.py INPUT.json --out-dir NEW_DIRECTORY`：INPUT包含period、asOf和companies代码，可选selectedId明确更正版本，或uploadedPdf补充文件。巨潮目录按请求分页获取，多个候选不静默选取。覆盖清单区分目录、披露线索、下载、解析与数值核验。
2. `python scripts/industry_financials.py INPUT.json --out-dir NEW_DIRECTORY`：已取得三表做季度计算；参数见[industry-financials.md](industry-financials.md)。
3. `python scripts/company_financial_report.py LINK.json --out-dir NEW_DIRECTORY`：LINK包含financialResult、originalResult、archives路径清单。核对代码、报告期，定位合并三表中支持字段当前列，原文明示人民币元、千元或万元时，换算至人民币元后与渠道原值逐项比较；输出匹配、差异、歧义或未定位。累计值匹配不证明单季值已核验。
4. `python scripts/financial_workbook_inputs.py LINK.json --out NEW.json`：准备Excel原始输入并重新核对财务档案哈希；可选commentaryResult附部分原文核验。
5. `node scripts/export_financial_workbook.mjs NEW.json NEW.xlsx`：需要Node和可解析的@oai/artifact-tool。可通过ARTIFACT_NODE_MODULES指定模块目录。五个工作表：财务概览、样本分组、季度底稿、原始字段、来源与覆盖。季度差分、同比环比、比率、样本中位数为Excel公式，逐项与Python结果核对。缺值留空，股票代码保留文本。RESEARCH_EXPORT_QA=1可附检查和预览。

流水线可用--node指定运行时。缺Node或Excel组件时，HTML、Markdown、JSON仍保留，Excel明确报告未完成；不安装额外服务或索取付费数据授权。

## 单季与同比环比输入原文核验

当用户要求核验单季变化时，在流水线输入增加`"verifyQuarterInputs":true`。流程从实际季度计算依赖中列出所需报告期，按需获取相邻报告，分别核对本期、同比基数、环比基数使用的累计输入。报告存在多版本时，不自动裁决；可用quarterReportSelections按公司代码、报告期指定selectedId、uploadedPdf或sourceDocument（字段同批量原文入口）。未请求时不额外下载多年报告。

已有归档可直接运行：`python scripts/quarter_original_review.py INPUT.json --out-dir NEW_DIRECTORY`。INPUT提供archive（三表result.json）、metadata（同季度财务研究）、period、originalResults（多期批量原文result.json路径列表）。每份已解析PDF重新核对哈希及分页文字，保留物理页引用和可携带原件。

输出七项支持字段的本期、同比及环比输入组状态。相邻报告缺失、字段差异或无法定位时不标记通过；有追溯重述提示时保留跨期可比性警告。该核验不证明完整报表或会计政策、合并范围一致，也不把数值匹配解释成经营原因已确认。

启用多期核验后，流水线在导出Excel前复核已保存的核验结果，将各组累计输入的核验状态、物理页码、差额和PDF哈希写入“来源与覆盖”。分步准备底稿时，可在LINK.json增加quarterReviewResults（单季输入核验result.json路径列表）；结果与底稿公司、期间、原始档案或重新核对状态不一致时停止导出，不能手动把未通过状态改为通过。

公告目录兼容“年一季度报告”和“年第一季度报告”、“年三季度报告”和“年第三季度报告”。摘要、主要经营数据公告及错误年份不作为定期报告；下载后仍核对PDF正文身份和报告期。

## 文本与结论

原文保留文件哈希、PDF物理页、证券与报告期身份。需求、订单、价格、库存、产能、风险关键词定位是线索，不自动作为经营原因。点评写已计算变化和有来源的待核实问题；不足样本不输出行业全貌或未来盈利判断。

当前数值核对支持营业收入、归母利润、营业成本、净利润、总资产、总负债、经营现金流；仅合并三表可解析版式，空白/单列/特殊财政年度、扫描件及修订差异需另核验。多个同名字段不裁决。

## 已验收与边界

中际旭创、立讯精密2026半年报与真实三表新标的试跑：各7项累计/期末数值与原文一致，Excel84项季度值与Python一致。只证明该字段/版式与本次样本，不覆盖任意公司的任意报告。全文提取不等于全文理解；未提供内置OCR或完整行业成分库。Word/PPT正式排版尚未产品化。

## 分步失败恢复

三表取数、原文获取、财务计算和点评分别记录结果。原文步骤失败时仍可保存已完成的财务计算；财务计算失败时保留取数及原文产出。依赖缺失的点评与底稿不强行运行，交付入口列出失败原因。重新运行使用新输出目录，避免覆盖旧研究。

交付入口另列 originalVerification：逐公司显示支持字段数、匹配数、差异数和未核验数。支持字段匹配完成也不代表所有报表科目或所有单季数字已核验。

万华化学2026半年报新增版式验收：无序号合并表标题、附注编号列及跨行现金流标签已支持，7项字段匹配。金额单位须明确且唯一；支持人民币元、千元及万元显式换算，未知、冲突或明确外币不直接混比。

点评和Excel底稿共用财务档案哈希绑定：来源文件必须与季度计算时一致，重复公司档案、缺档案或文件变化均停止该输出，不能混用新旧版本。

已解析原文需保留归档中的代码目录/report.pdf。生成点评和底稿时核对原件存在及文件哈希；原件变化需重新解析。统一财报复核模板将PDF登记到本地依赖中，供旧结论失效检查使用。

## 带证据的经营点评

company_financial_report 的 LINK.json 可选 interpretations：每家公司 code、entries；每条 entries 提供 text、basis（company-statement 或 research-explanation）、evidence（page、quote）。解释由AI根据实际原文组织；程序验证引句页码和文字定位，不自动证明解释正确。无法解析原文、公司不在计算样本或引句不存在时拒绝该点评。报告区分公司陈述与研究解释，累计期间原因不改写为单季度因果。

完整财报流水线也可传 interpretationsPath，或直接提供 interpretations 列表；格式同点评入口。文件读取、列表格式及参数冲突先在取数前检查；原文引句或证据核验失败发生在点评阶段，已完成的取数及财务结果仍保留，点评状态单独记录失败。


样本点评同步列营收、归母利润及经营现金流同比中位数、有效家数与缺失家数，并保留groupCommentary。仅一家有效时不作横向比较；缺失不按零处理。分类版本、报表范围及币种分别列明，指定样本不升级为全行业结论。


三一重工2026半年报新样本已验证千元整数、带顿号附注编号及跨行归母利润。七项支持字段换算后匹配，完整流程交付覆盖清单、点评及Excel，公式检查无差异。核对保留原文数值、金额单位、换算值及披露精度容差：整数千元的舍入容差为500元；在容差内匹配不等于逐元精确披露。


工程机械指定双样本（600031、000425）2026半年报全流程验收：两家各7项支持字段与同期原文匹配。Excel另核季度值、同比环比、公司比率、分组中位数与各指标有效家数，共152项无差异；分组家数不一致时停止导出。分组总家数与各指标有效家数分列，不能将两家公司外推为全行业。


公司点评、公司简报使用绑定原文时，除PDF哈希外还重新解析页码文字。保存文本被改写时停止原文引用核验，要求重新解析，不沿用被改写的数字或引句。批量原文获取记录解析器；此前本入口的PDF资料按其固定pdfplumber解析方式复核。


### 跨公司经营与风险对照

公司点评输入可选`comparisons`：每项含`codes`（至少两家本次样本）、`kind`（agreement/difference/not-comparable）、`basis`（research-explanation）、`text`及`evidence`。每条证据含`code`、PDF物理`page`和原文`quote`，必须覆盖每家参与公司。只将对照标为研究解释，不以一致表述代替行业共识或验证因果。

输出同时包含季度财务、分组中位数、逐公司解释与跨公司对照；随报告复制绑定PDF到`sources/`，数字核验和经营解释提供原文页码链接。三一重工、徐工机械2026年中报已用于真实样本验收；样本对照不代表全行业覆盖。

统一财报流程`financial_research_pipeline.py <input.json> --out-dir <目录> [--node <Node路径>]`支持直接传入`interpretations`和`comparisons`，或分别使用`interpretationsPath`、`comparisonsPath`读取列表文件。同一项不能同时给文件和直接内容；冲突或列表格式不符时在取数前停止；证据不足时单独记录点评缺口，保留已取得的三表及财务结果。对照原文要求与单独点评入口相同。

点评和Excel底稿使用财务快照前，从绑定的三表档案重新计算公司指标、比率、规则提示和分组统计。保存结果与重算不同则中止，不把已改写的指标继续包装为来源可靠的成果。三一、徐工真实档案已验证正常重算及指标、提示、分组值改写拦截。

已另用长江电力2026年中报进行跨行业样本验收：自动获取三表和原文、7项支持字段匹配、78项Excel公式值复核，并定位来水、电力市场、安全生产三项风险解释。此验收仅覆盖支持字段与选取段落，不等于水电全行业或完整尽调。

Excel引用点评的原文核验状态前，验证点评所绑定财务/原文输入哈希、公司集合与报告期，并从原文重新计算支持字段的核验结果。保存的“已匹配”等标签若被改写，不继续作为底稿的核验依据。未提供点评时不自动填入“已核验”。

跨期比较另检测报告前部明确披露的“本报告期对比较期间财务数据追溯调整”。命中时，点评、简报及Excel来源说明提示历史渠道值未确认使用同一重述版本；当前列7项数值匹配不能证明同比或单季差分口径一致。该检测仅为已支持措辞的线索，不保证识别所有会计政策与合并范围变化。长江电力中报第7页已用于真实验收。


联动报告保留追溯调整提示：本期累计值或期末值匹配，不确认比较期间数据或同比口径。原文披露追溯调整时，研究入口同步显示原文页码与同比复核要求，不能用全部支持字段匹配覆盖此缺口。


## 同档案跨期财务对照

用户询问公司前后季度变化时，复用 industry_financials.py INPUT.json --out-dir NEW_DIRECTORY --compare-periods。输入沿用 companies 中的 archive、metadata，另指定 beforePeriod 与 period（递增自然季度末）。输出 JSON、Markdown、HTML，分别列单季利润/现金流与期末资产负债；缺值不算差额。

该入口从同一已取得档案重算两个报告期，不是历史时点快照回放。声明单位不等于已核验单位，两期原文、重述及范围变化须另核；不能仅凭差额判定经营改善。


跨期输入最小模板（路径和元数据须替换为已取得的真实资料）：

```json
{"beforePeriod":"2026-03-31","period":"2026-06-30","companies":[{"archive":"/absolute/statements/result.json","metadata":{"name":"目标公司","group":"指定样本","classificationVersion":"用户分组v1","sectorType":"general","scope":"consolidated","currency":"CNY","unit":"渠道原单位（待原文确认）"}}]}
```

```text
python scripts/industry_financials.py period-input.json --out-dir new-period-review --compare-periods
```

输入1至20家不重复公司。报告期不是自然季度末、顺序不递增或声明币种与资料不符时拒绝；披露晚于档案截止日的数据不参与计算。


贵州茅台中报已验收纯数字附注列：表头明确附注且数据行含编号及两期数值时跳过编号；只有两期数值时不跳过本期整数。此规则不确认全部附注或所有版式。


收入比率口径：当前净利润率为净利润除以营业收入。当渠道同期营业总收入与营业收入均可得且不同，点评、公司简报及Excel提示分母差异；不将其称为营业总收入净利率，不仅凭差额推断金融业务贡献。缺失或冲突字段不据此判断两者相同。


## 目录接口失败时的明确原文入口

AI已找到巨潮PDF原文时，可在公司项传 sourceDocument（code、id、title、publishedAt、url），复用 company_report_batch.py 或财报联动流程。网址须为 https://static.cninfo.com.cn/finalpage/披露日/公告ID.PDF，日期在报告期与截止日之间；下载后仍核验PDF代码及报告期。不得同时给 uploadedPdf 或 selectedId。

该入口保留 sourceType=cninfo-explicit-url、元数据按输入声明的状态；不把目录未运行写为目录已核验，也不凭搜索标题确认全部公告版本。目录失败记录单独保留，不能因此宣称报告未披露。


明确原文链接或补充文件的元数据待核验状态，会继续显示在点评、公司简报、研究入口及Excel来源说明。支持字段匹配不消除披露日期、版本关系的缺口。

### 竞争优势与待核实问题
经营点评可在原文引句旁附 `followUp` 非空文字列表。它只表示尚待核实的问题，不构成已验证证据或护城河评分。公司对竞争力的自述须与研究解释分开；比较品牌溢价、渠道质量或优势持续性时，应补齐同口径经营指标与反证。

研究首页将支持字段中的尚未核验项和原文差异项列入资料缺口；各阶段执行完成不等于数值核验通过。

财报联动调用前须明确每家公司的报表范围（合并/母公司）、币种、单位与分组版本。缺失或空白时先补齐，不启动采集；单位未知可明确登记“渠道原单位待原文确认”，但不能将其当作公告已确认口径。

整体交付状态：deliveryAssessment 分开判断步骤是否生成、原文支持字段与比较列是否匹配、相邻期单季输入是否核对。步骤执行完成而数据有缺口时保留 partial；全部通过也仅为 supported-scope-verified，不能宣称全三表或全行业研究完成。

标题识别统一支持含“年”及不含“年”的自然年报告标题，例如2026年半年度报告与2026半年度报告。季度报告的一季度/第一季度、三季度/第三季度写法也在目录与正文身份核对中保持一致。仍排除摘要、英文、取消与作废，并核对证券代码、报告期和截止日；标题匹配不等于数值核验。


银行合并及公司并列报表：仅在明确“本集团 / 本行”、四列年份和人民币单位声明时解析；支持百万元单位、归母净利润两列归属行及跨行现金流字段。营业支出不替代营业成本。仅核验支持字段，未覆盖银行全部专属科目；普通公司预测模型不适用于银行。


### 跨渠道文件、日期与页码
同一公司的同一期报告可能有海外监管公告封面或附件包装。文件哈希不同，不直接判为财务更正，也不静默合并。先分别记录目录发布日期、公告署名日期、董事会批准日期及来源市场；需要对照时明确页码偏移，逐页比较正文并说明比较范围。提取文本一致仅说明文本层一致，不证明图片、签章或二进制一致。页码引用必须绑定具体文件哈希。缺乏历史公开记录时，不宣称已核验首次公开时点。

银行报告可使用“未经审计合并报表”、人民币百万元列示、分行年份/日期表头以及“本行股东的净利润”等表述。只在明确表头对应时核验比较列。银行利润表跨页重复同一净利润且值与单位一致时保留全部页码；不同值仍保留歧义，不静默取其中一行。

合并报表之后出现不带“合并”字样的独立报表标题（例如“未经审计利润表”）时，停止当前合并报表采集，避免把母公司数值计入同字段。单季度、同比基数及环比基数分别核验所依赖报告，不用单份半年报的通过状态替代四期输入核验。

### 季度核验结果的版本校验

再次使用已保存的季度核验结果时，会检查计算、原文核验和报告标题解析的方法版本。版本发生变化或旧结果缺少完整留痕时，需要重新核验；不能直接沿用旧核验状态。原始资料及旧结果保留，重新核验另存输出目录。

金额单位声明仍含待确认、未知等状态时，财务计算保留口径缺口，点评和Excel来源页沿用同一提示。数值匹配不自动改写单位声明；明确单位及来源依据后应另建计算与交付版本。

流水线交付总状态同时检查点评登记的研究缺口。获取、计算、导出均完成且支持字段匹配时，若单位声明或其他研究缺口仍未解决，交付保持部分完成，不以字段匹配覆盖缺口。

经营点评中的 followUp 待核实问题同时进入研究缺口清单，不仅展示在正文。引句可定位不表示问题已取证；整体交付状态不会因财务字段匹配而隐藏这些问题。

Excel 导出保留经营点评中的待核实问题，每项列出原文页码、文件哈希和未验证状态。导出前检查问题是否同时出现在研究缺口清单；遗漏时停止导出并提示补全。原文引句定位通过不表示待核实问题已有结论。

报告身份核对共用同一规则：所属期标题可去除版式空白，证券代码在保留文本边界的前12页核对，避免代码与年份拼接或长号码误匹配。遇到多个报告版本，覆盖清单展示标题、披露日期、公告编号和原文链接；明确版本后再下载核验，不自动裁决更正版本的适用性。

汇总报告的资料缺口同时包含流程失败与交付评估确认的研究缺口，去重后保留；不可仅用下载或导出成功作为完整交付证明。Excel 的同期报告记录保留解析失败原因。

已确认存在附注列的三表支持“七（61）”等中文括号附注编号，编号不作为金额或年份。未确认附注列时不自动删除该文本；并列表、未知附注布局仍保留歧义。

批量取报可在输入中指定 `resumeFrom` 为上一批 `result.json` 的路径。报告期、截止日和公司集合必须一致，输出使用新目录。成功项重新核对PDF哈希、报告身份及解析内容后复用，失败项重新采集；缓存缺失、损坏或解析变化时重新采集并记录原因。明确指定新原文、上传文件或公告版本时重新获取。复用本地原文不代表已检查远程更正公告，数值核验仍需另行执行。

完整财务研究流程可用 `originalResumeFrom` 指向此前主报告取报批次的 `result.json`。相邻报告在 `quarterReportSelections[公司代码][报告期].resumeFrom` 指定对应单公司批次；仍按原文续采规则核对截止日、报告期及公司集合。仅复用原文，结构化三表重新取数、财务计算及原文数值核验重新执行，不沿用旧点评或核验结论。

财报覆盖清单和研究首页列明本次复用原文的公司、尝试重新获取原文的公司，以及未检查远程更正的公司。重新获取仅表示进行了获取尝试，成功或失败仍分别查看覆盖清单；本地原文重新核对不表示已确认最新公告版本。

续采同时检查批次与每家公司保存记录的报告期、公司代码及截止日。单公司记录不一致时不复用该项，重新尝试获取并记录原因；不以PDF内容匹配覆盖记录身份冲突。

点评列表及文件输入在取数前检查。直接内容和文件路径不能同时指定同一类点评；文件不存在、内容不是列表或 JSON 无法读取时先纠正输入，不创建交付目录或发起三表及原文采集。

相邻期输入汇总同时保留原文披露日期、版本关系及跨期可比性提示。即使各项数值匹配，这些提示未解决时仍列为交付缺口，不升级为支持范围全部核验。

币种字段与“审计类型”标签紧排时，按明确标签分隔识别人民币；未知或冲突币种仍不换算。版式修复后重新核验另存结果，不改写历史核验。渠道历史值与旧报告不一致时保留差额，不自动断言重述、造假或数据错误。

单季输入报告对未通过项给出可读说明：数值差异展示渠道累计或期末值、原文换算值、差额（渠道减原文）及页码；单位或币种未确认时只说明无法比较，不计算差额。报告缺失与数值不一致分别列示，差异原因尚未取证时不自动归因或选值。

主要会计数据表明确并列“上年同期调整后／调整前”时，输出比较基数版本提示并绑定页码。数字匹配其中一列不确认相邻期间采用相同调整，也不解释调整原因；旧报告与新版比较列不直接混用。一般性会计政策讨论不作为已发生重述的证据。


## 按需导出 Word 和 PPT

在流水线输入增加 `"exportFormats":["docx","pptx"]`，可只请求其中一种；默认不导出。格式列表须合法且不重复，在取数前检查。点评完成后使用新生成的正文与哈希导出，复用其原文页码和来源副本。Word需要python-docx，PPT需要Node和演示文稿组件，运行条件见[财务研究导出](industry-financials.md)。

导出结果分别列于 documentExports。文件生成后标为 generated-awaiting-review，仍需最终文件及逐页排版验收，不以生成成功消除数据缺口。一种格式失败不丢弃另一种格式、Excel底稿或已有原文与计算。点评未完成时记录依赖缺失，不生成空白报告。originalResumeFrom 必须指向归档 result.json 文件，不能填写目录。


## 深度研究的组织与交付

深研执行按[研究流程](research-operating-flow.md)组织问题、证据任务、经营机制与适用估值，交付按[深度研究标准](research-depth-standard.md)复查。当前脚本完成取数、核对或格式导出，不自动完成商业模式、原因和投资价值判断。已有数据足够时继续分析；关键资料失败时说明其影响并交付有限结论，不将研究提纲称为完整深研。

## 导出环境配置

流水线可用 `--node <Node可执行文件>` 和 `--artifact-node-modules <组件目录>` 明确配置目标环境。环境检查使用相同参数；也可通过 ARTIFACT_NODE_MODULES 提供组件目录。路径仅在本次调用使用，不写入安装包，不安装组件或搜索作者电脑目录。组件目录无效时在取数前停止。

```bash
python scripts/environment_check.py --out local-data/environment.json --node /path/to/node --artifact-node-modules /path/to/node_modules
python scripts/financial_research_pipeline.py REQUEST.json --out-dir NEW --node /path/to/node --artifact-node-modules /path/to/node_modules
```

先由AI确认宿主提供的实际路径，不能原样使用示意路径。默认组件可通过 Node 解析时无需这些参数。

Excel完成状态要求生成有效XLSX结构、存在公式差异核对记录，并且记录中的输入与工作簿哈希匹配。样本分组单独成表，数字保持数值类型，缺值留空。公式匹配不代表原始资料真实、全部科目核验或跨期口径一致；仍须读来源与覆盖及研究报告缺口。

## Word与PPT核对

需要Word/PPT时声明 `exportFormats`；请求PPT时同时提供已确认目标环境可用的 `fontFamily`，流水线将其传递到导出器。缺字体或组件只影响该格式，其他成功成果保留，不安装软件或默选未经确认字体。

导出完成后，可运行 `python scripts/verify_document_export.py NEW/export-result.json --markdown SOURCE.md`，核对成品、已保存正文和随附原文哈希，检查Office结构与可编辑正文。PPT另检查页数和记录中的正文保留情况。此检查不证明研究结论正确或视觉排版合格。

Word需用目标环境可用的文档渲染器查看全部页面；PPT查看全部导出页图。缺渲染依赖时保留“排版待验收”，不能以文件生成替代。报告中本期、比较列和相邻期单季输入的核验状态分别保留。


历史报告宽窗口目录未命中时，额外回查较窄披露窗口（不晚于截止日）：年度报告至次年6月30日，其他报告至次年3月31日，分别保存请求和响应；以实际标题、代码与日期筛选，版本冲突仍要求明确选择。该回查不证明目录完整或没有更正，未命中不等于未披露。

合并范围复查另保留后部附注中“其他原因的合并范围变动”明确勾选适用的线索，含物理页及节选。仅支持该措辞与勾选结构；未命中不证明范围未变，命中不量化注销、新设等影响，也不直接判定季度差分失效。新方法须用原文重跑，不能沿用旧方法认证。

候选重复公告ID且全部元数据相同可去重；同ID不同标题/日期/附件保留冲突并停止，不任取。上传和最终PDF均限64MB。上传原件解析成功不认证来源或披露时点；数值核验、点评和视觉状态分别记录。
