# 研报精读与跨报告对照

用户上传一篇或多篇PDF并提出“精读”“比较观点”时使用。复用已有文档读取能力的原则，但本入口单独保留通用研报原件与物理页码，不依赖基金报告版式。

## 读取与归纳分工

脚本准备PDF文字、保存哈希和页码，并校验摘要引句能在指定页定位。AI阅读材料并完成三层归纳；脚本不会通过关键词自动生成投资逻辑，也不把引句存在当成概括正确。

1. 核心逻辑：报告真正主张什么，驱动链如何成立；区分作者观点与已披露事实。
2. 假设与证据：列出关键前提、数据日期、口径和结论失效条件。风险段落与正文一起读，不能因为列在风险提示里就推断是作者唯一真实判断。
3. 研究深度：区分公司披露、第三方转引、调研记录和作者推演；记录证据是否有主体、样本、时间和方法。没有一手调研不等于报告没有价值，不制作无依据质量评分。

跨报告比较先对齐标的、期间、定义与发布日期。区分一致、分歧和不可比。机构不同不证明证据独立；同一公告被多次转引不增加独立证据。没有外部共识数据时，不称为“市场预期差”。

## 最小端到端调用

先由AI准备输入；日期和机构缺失留空，不从文件名猜测。

```json
{"asOf":"2026-10-05","reports":[{"id":"report-a","pdf":"/absolute/report.pdf","title":"用户提供报告","institution":null,"publishedAt":null,"originGroup":null}]}
```

```text
python scripts/research_report_reading.py prepare input.json --out-dir new-archive
```

读取 `new-archive/result.json` 内每页正文，并按需查看原PDF图表。实际文字确定语言；扫描页标记人工辅助，pdfplumber失败或文字不足时尝试pypdf。两者都不足时不生成已完成精读。每次最多20份、单份64MB/800页。

```json
{"archive":"/absolute/new-archive/result.json","analyses":[{"reportId":"report-a","logic":[{"text":"AI依据原文写出的核心逻辑解释","evidence":[{"page":1,"quote":"这里必须填第1页真实存在的引句"}]}],"assumptions":[{"text":"关键假设及证据限制","evidence":[{"page":2,"quote":"这里必须填第2页真实存在的引句"}]}],"depth":[{"text":"证据类型与建议精读的位置","evidence":[{"page":3,"quote":"这里必须填第3页真实存在的引句"}]}],"gaps":["尚缺哪些验证依据"]}],"comparisons":[]}
```

```text
python scripts/research_report_reading.py build reading-input.json --out-dir new-reading
```

后三层示例引句是格式占位，必须用实际文字替换，否则校验拒绝。国金报告已验收摘要及六个正文引用页，仍不声称全文逐模块已验证。长江报告另有12页人工视觉阅读记录，普通文字解析仍不足，不能称自动引句核验通过。build在全部校验通过后写新目录，原PDF变化需重新解析，输出JSON、自然语言Markdown和HTML。

跨报告 `comparisons` 每行提供 `kind`（agreement/difference/not-comparable）、`text`、`reportIds`，以及 `evidence`：每个参与报告至少一条 `{reportId,page,quote}`。所有参与报告必须已有三层摘要。对照文字仍由AI判断，程序仅核查引用覆盖与定位，并提示来源独立性未经外部核验。

## 精读路径与语言处理

宏观框架重点读情景条件、变量方向和时间；行业公司重点读经营驱动、分部数据和估值假设；调研型材料重点读受访主体、样本与证据来源。精读优先级结合用户问题、证据新颖性与尚未解决的分歧解释，不使用虚构评分。

英文原文由AI根据用户提供或有权处理的文档逐段翻译，金融术语保留英文。交付入口为 `python scripts/report_translation.py INPUT.json --out-dir NEW_DIRECTORY`；它核对译段绑定的原文覆盖、页码和数字，不能自行调用翻译模型，不保证语义、复杂表格或原PDF版式还原。提取不到的图表与公式保留缺口，不补造。

INPUT含 archive（prepare结果路径）、reportId 和 pages。每页提供 page 与 blocks，每个段落提供 sourceText（原文完整段落）和 translation（中文译文）。同页所有 sourceText 按顺序连接后必须覆盖该页全部已提取文字，不能只用核心引句冒充全文。译页按物理页排序，不重复。未提供的页及文字不足页单列；覆盖全部提取文字仍不证明图片、公式或全文语义已核验。

输出独立中文 HTML、Markdown、result.json 及原PDF副本。每页可打开原件；阿拉伯数字的写法或出现次数变化会提示人工复核，包括合法的日期、单位换写。没有数字提示不证明百分号、正负号、单位、上下文或翻译意思正确，必要时仍逐项人工核对。

## 输出与失败处理

报告先讲各篇结论及依据，再讲假设、精读重点与对照，最后列未读报告和资料局限。原作者的建议只作为其观点描述，不改写成给用户的交易指令。

单份读取失败不影响其他报告归档。错误引句、重复ID、未来披露日期、原件哈希变化会被拒绝；需修正或重新解析。扫描件和低文字页面必须查看原件；无内置OCR。没有取得资料的报告保留为未读，不从标题编摘要。

## 可携带的原文引用

精读交付目录含 sources/ 中本次归档中取得且通过哈希核对的原PDF副本（包括尚未精读或正文不足的报告），正文的物理页码链接可直接打开对应页。result.json 保存副本相对路径及文件哈希。分享时连同整个交付目录移动，避免单独发送HTML导致原文链接失效。原件副本只用于本次有权处理资料的交付，不进入独立安装包。


跨报告对照也提供各参与报告的原文页码链接。已使用三一重工与徐工机械2026年中报验收经营模式、全球化及风险段落，校验六条分层引句和两项跨报告对照；不代表全报告尽调或外部确认公司观点。

原文证据复核：生成报告前，按记录的解析器重新提取绑定PDF的页码文字，并与保存文本比较。PDF哈希、页码文字任一变化均阻止引用通过；旧资料缺少解析器记录时需重新准备。此项只确认文字来源，仍不替代摘要的语义复核。


## 公司产业链阅读

用户询问公司的上游、生产、销售渠道和下游时，复用上述 prepare/build，不新增菜单或要求用户填写参数。AI从实际报告中整理，并在对应 analyses 项增加可选 industryChain。

industryChain 接受 upstream、manufacturing、channels、downstream 四个列表；每项沿用 text 和 evidence 的页码引句格式。缺资料的环节用空列表，不补造；gaps 为文字列表。至少一个环节有据才能生成产业链说明。错误页码或不存在的引句会阻止交付。

输出分环节说明及原文链接。采购品类不当作已核验供应商，应用行业不当作具名客户；没有交易金额、终端销量和订单数据时，不计算交易依赖、供需缺口或景气拐点。关系解释由AI根据原文形成，程序确认引句来源，不自动证明解释正确。

跨报告比较同时列明参与报告数量、不同PDF数量、已声明来源组数量与未确认来源数量。相同PDF或同源转述不增加独立证据；来源组不同仅为输入声明，不证明事实已获独立核实。参与报告代码不得重复。

## 部分成功时的完整交付

例如用户上传两份PDF：A可读取，B正文提取不足。AI只对A写三层精读；`analyses`不添加B，也不创建A/B的`comparisons`。B保留在归档和未读清单中，注明“正文提取不足，需人工辅助读取”，并附可打开的原文副本。没有取得B原件时说明文件缺失。不能将未读解释为观点缺失或没有风险。

`build`输出主要字段：`analyses`保存已定位的摘要引句；`comparisons`保存有足够参与证据的对照；`unreadReportDetails`保存未读标题、状态及原因；`sourceFiles`保存原件相对路径、哈希与是否已精读。`originAssessment`列参与数、不同文件数、声明来源组数和未知来源数；这些计数不构成可信度评分。

分享整个交付目录，用户打开HTML即可阅读自然语言摘要并跳转原文。归档原件出现变化时先重新准备，不沿用旧页码。失败不抹去已成功阅读的其他报告，但不输出缺证据的跨报告判断。

## 政策原文解读
`analyses`可增加 `policyAnalysis`，包含 scope（适用对象与工具）、timing（公布及生效）、transmission（传导解释）、risks（条件与风险）四个引句条目列表。每项仍为 text/evidence；缺资料保留空列表，至少一项有原文。公布日不等于生效日，历史文件不证明当前有效。传导解释不构成因果验证、法律判断或投资建议。

原文副本保存 sourceUrl 和元数据声明状态。转载地址不得写成发文机关下载页；机构名称、登记日期和来源网址仍需独立核对，PDF文字可定位不证明来源身份已验证。

交付逐篇列出引用页码与文档总页数，仅代表引句定位范围，不据此宣称全文核验或准确率。跨报告对照分别标注一致、分歧与口径不可比。

可选 dueDiligenceQuestions 用原文页码形成访谈提纲，每项包含 respondent（management/customer/supplier/distributor/competitor/analyst）、question、requestedEvidence、evidence。仅准备问题，不联系受访者、不生成访谈答复，不将公司披露视为独立访谈证据。最多30项；无原文依据或缺少待取材料时拒绝。

## 跨报告的底层来源

对照项可增加 `underlyingSources`，键为全部参与报告ID，值为已从引句和上下文登记的来源名称列表；未知关系用空列表。公司财报对照沿用此字段，键为参与公司代码。报告会列出共同登记来源，重复转引不增加独立证据。

例如两份报告都引用奥维云网同一期间、同一口径的家电零售数据，登记 `{"report-a":["奥维云网：2026H1国内家电零售"],"report-b":["奥维云网：2026H1国内家电零售"]}`。不同统计期间或品类不要合并成同一标签。标签和转引关系由阅读者确认并声明，程序仅校验结构和重复关系，不自动核验原始第三方数据或计算证据可信度。报告中的 `independentEvidenceConfirmed` 保持 false，不能用声明的不同来源数作为已独立验证次数。


## 章节范围与印刷表格

analysis 可含 sectionReviews：title、startPage、endPage、status（reviewed/pending）、note、evidence。范围须为PDF物理页，引句在该范围内；阅读完整性是本次声明，不因引句存在而证明整章解释正确。pending 进入资料缺口。

numericTableChecks 每项含 page、tableTitle、columns、headingQuote、rowLabel、rowQuote、values、unit（percent/number）。按标题后的同一表格范围定位列头及指标行，逐列核对印刷数值和百分号；同页其他表的同名指标不能替代。values 为印刷数值，如24.68%，填写24.68和percent，不能填写0.2468。复杂行列或图片曲线不自动还原，保留人工复核缺口。

结果输出章节阅读范围和印刷表格核对。数值匹配不等于原始回测复现，不核验底层样本、交易成本或未来有效性。


基金报告可在单篇 analysis 中指定 `benchmarkReview: true`，自动核对已解析正文中的基准表述并输出页码。未设、未定位、公式待核验、表述冲突分别处理；不据此确认合同有效性，不自动套用指数。默认不触发。


## 跨报告比较口径登记

每项 comparisons 可增加 comparisonBasis，按 reportId 登记 subject（比较对象）、period（期间）、definition（指标或观点定义），三项均为非空文字，必须覆盖全部参与报告。例如：`{"report-a":{"subject":"经营现金流","period":"2026上半年累计","definition":"经营活动现金流净额"},"report-b":{"subject":"经营现金流","period":"2026第二季度单季","definition":"经营活动现金流净额"}}`。

程序比较登记文字；任一项不同，在正文说明不能将差异直接当作同一问题上的冲突。全部相同仅表示登记口径一致，仍需AI检查语义和原文，不能据此确认事实正确。未登记时明确提示只作观点对照。跨公司研究若对象本就不同，应按真实对象登记，保留不可直接比较提示，不为通过检查改写对象。

比较标题与口径状态联动：口径尚未登记时显示“观点对照（口径待确认）”；已登记但对象、期间或定义不同，显示“口径不可直接比较”。输入作者分类保存在 kind，实际呈现分类保存在 displayKind；标题不把未确认口径包装成一致性结论。

逐页语言提示：prepare 与 build 按提取正文记录各页语言倾向，英文页在精读正文中单列。中文报告中的英文附录不会被整篇标签隐藏；文字不足页仍标记待人工核对。字符比例仅用于安排阅读，不证明已翻译或语义识别完整。

## 假设核查计划

单篇 analyses 可选 assumptionTests 列表（最多30项），每项含 text、evidence（page/quote）、invalidationSignal（需要留意的反证信号）和 requestedEvidence（待取材料）。脚本重新解析原PDF定位引句，输出核查计划并登记研究缺口，不接受输入自称 verified。该计划不证明假设成立、因果传导或预测有效；后续取得材料需另行核验。

共用研究入口同时把假设核查计划登记到结构化缺口清单，保留 reportId、invalidationSignal、requestedEvidence、evidence 和未验证状态。保存版本摘要覆盖这些内容；研究汇总不能把假设计划当作已完成取证。

### 多层分组表头

印刷数值核对遇到重复列名时，须提供与 columns 等长的 columnGroups 及 groupHeadingQuote 原文。每个组连续，同组列名唯一，分组表头在同一表格列头之前，组名和列名的顺序都必须定位。报告显示“分组／列名”，避免将绝对收益与超额收益混用。组列对应仍是显式声明，文本顺序定位不等于图形坐标核验；交错布局、组头缺失或顺序不一致拒绝自动核对。

精读结果保存原文哈希之外，也保存解析与表达、章节及数值核对的方法文件哈希。统一研究快照的影响检查分别检测本地输入和方法变化；旧快照失效时另建版本复核，不覆盖旧结果。方法未变化只证明已登记本地依赖一致，不证明远程原文没有更正，也不证明研究解释正确。

译文数字提示同时检查明确正负号、百分号及 percent、billion／million／trillion、亿／万等数量级写法。percent 与 %、常见负号字符规范为同一写法；合理的数量级换算仍可能出现提示，需说明换算依据。该检查不理解“下降”等文字含义，也不确认全部货币单位、分数、公式、图表或数值对应关系。
