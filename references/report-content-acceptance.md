# 报告内容验收

用于研究点评、比较和诊断的最终正文检查；单字段查询按实际请求简化。自动结构检查与AI内容复查分别记录；AI复查不称独立专家评审。

## 增补后的阅读顺序

新增证据或分析后，重新阅读全文并放回对应论证位置，不默认追加到报告结尾。先给总体判断，再展开分维度论据和竞争解释，最后说明改变判断的信号、已回答问题与剩余缺口；原文核对明细可置于附录。新分析若改变原判断，需改写开头；未改变则说明它支持或限制哪项判断。完成重排后重新绑定最终正文版本，保留旧版，重新检查相对链接与选定证据。正文可重现、引句存在不证明视觉效果或判断正确。

证据取得或计算完成后，逐处复查正文、结论限制、内容复查理由及当前缺口清单中的旧状态。区分“该次取得失败”“现已取得选定原件”“该指标已复算”和“全历史仍未核验”，不能一边展示新核验结果，一边沿用该指标尚未完成的旧说明。旧失败记录独立保留；只收窄实际已解决的缺口，不由一次成功消除其他期间、字段或研究问题的限制。

## 验收方法

阅读实际生成正文及其对应输入、原文和计算结果，逐条记录“通过、部分、未通过、不适用”，附具体段落、证据位置和理由。先确认交付层级：资料核对、历史表现比较、专题评价或完整深度研究。不要让窄范围比较冒充完整评价。

|检查项|检查内容|
|---|---|
|结论与问题|开头回答用户问题，明确主体、期间和适用范围；结论突出，论据放在后续段落或附录|
|论据与数字|每项关键判断有可定位依据；核对正文与底稿、单位、累计/单季和比较基数|
|变化的含义|说明业务或风险意义；原因未验证时写有限解释，不把相关当因果|
|竞争解释|因果判断保留相关替代解释；纯历史差异比较不强加虚构原因|
|反证与跟踪|写出改变判断的可观察证据；不只列通用风险|
|缺口的影响|说明缺少哪些资料、阻断哪个结论；成功部分仍可交付|
|可比性与比例|频率、币种、分红、基准与样本一致；正负翻转、接近零或极端变动率需核对基数，优先解释绝对额与方向|
|适用依据|具体制度结论核对官方版本和适用对象；专业方法、产品条款与法律分别标注，缺证据不认证合规|
|名称与范围|没有持仓、基准、经理等资料的净值比较，不命名为完整基金评价；单公司不冒充行业判断|

所有必需项通过才能标为“在声明范围内内容复查通过”；任一项部分或失败则保留部分状态。不用条数、章节数、结构字段或主观评分代替判断。未读取原文的引用检查标未完成；没有浏览器或分页图检查时，视觉状态单列未完成。

核心结论须声明 `requiredEvidenceIds` 并绑定相应证据。验收索引发现未声明依赖时，即使其他复查项声明通过，也列为内容缺口；缺少已声明的必需证据则绑定失效。旧格式仍可读取，但不能因为可读取就认定依赖完整。声明只是确定本次计算和论证需要哪些输入，不自动证明这些输入足以支持结论。

## 内容记录

组合评价额外检查总体判断是否被正文支持：至少说明所用证据属于静态快照、历史路径或用户真实账户中的哪一种；同一报告中不同权重模型、日期和单位分别解释，不合成为未经核验的账户结论。检查结论是否回答风险问题，而非只复述最大回撤和相关性数字。用户目标缺失时可保留有限结构判断，不能填造目标、健康评分或建议权重。选定一段历史支持的分散评价，不能扩大为未来保护效果。

记录日期、报告路径或文件标识、正文哈希、样本、研究范围、各项判定和原因、复查方式、整改及剩余缺口。记录不自动证明数据真实、因果成立、投资价值或跨环境可交付。历史记录不能作为本次新生成报告的验收结果。

本次选定报告复查见[2026-10-06记录](validation/content-review-20261006.json)。该记录是已有真实样本报告的AI复查，未新增联网采集或独立专家评审。


## 评价文章：建立判断

先回答“怎样评价、为什么”，再介绍对象。开头交付有范围的一句话判断与核心矛盾；已有印象只作为待验证命题，不能代替事实。正文按与判断相关的维度论证，每个维度说明：观察到什么、意味着什么、哪条证据支持、有哪些反对证据或竞争解释。结尾给研究定位、适用条件及改变判断的信号，不用通用风险列表代替反证。

结论字号与层级突出，原文引句、公式和明细放后。用“利润增长是否转成现金”等具体问题，避免只写“盈利能力、现金流分析”等目录标签。没有足够依据时直接结论为“尚不能判断某项能力”，说明阻断它的缺口；不为写评价编造原因、分数或推荐。

公司解释条目可提供`coreTension`、`judgmentBoundary`、`positioning`，各为360字以内单行文字；已有结论、原文证据、竞争解释与反证字段继续复用。定位指研究上的优势、限制与适用情景，不是买卖指令或目标价。结构合格不等于结论可信，仍需逐段原文与逻辑复查。基金、ETF、组合、行业、宏观及北交评价采用相同文章逻辑，具体证据按各场景取得。


基金双产品历史报告先说明收益与最大回撤之间的取舍，或在这两个维度上的样本内领先。不得将该结论提升为经理能力、未来优势或完整投资价值。只有两只产品且指标完整有限、回撤非负时生成此比较；数据不足时明确不作取舍判断。基准、分红、费用、经理任期等边界仍需从原始研究结果核对，不能由报告生成器补造。


逐项内容记录可调用`report_content_review.bind_review(spec)`，输入实际reportPath、正文reportSha256、reviewer与九项checks，每项保留key/status/location/reason。正文修改、漏项或理由为空拒绝沿用。只绑定声明完整性与正文版本，不执行语义认证；任何部分或失败不得标全通过。实际链路复查例见[工业富联记录](validation/p0-chain-content-review-20261006.json)。


现金兑现评价优先读取现金流量表补充资料的利润到现金调整，不只看应收、存货余额。经营性应付增加可能抵消占用，需同时说明；经营性应收/应付不等同于单个资产负债表科目。选定调整项加差额只能称有限桥接，不能宣称全部原因核验。半年桥接不能直接解释单季差分。反证必须固定复查报告期并注明比较口径，避免事后更改标准。


关键派生比例逐项登记原文页码、输入金额与单位、公式、显示精度及比较基数。合并净利润与归母净利润不可混为现金利润比分母；同比、上年末变化与单季差分分别核验。只核过一组比例时，注明选定范围，不标整份报告全部数字核验完成。


## 结论与研究范围绑定

调用report_content_review.bind_claims(spec)，提供reportPath、reportSha256、researchLevel、answeredQuestions、unansweredQuestions和claims。研究层级限定为data-check（资料核对）、historical-comparison（历史比较）、focused-appraisal（专题评价）、deep-research（深度研究）；层级声明不自动证明完成。每条核心结论提供id、conclusion、limitations，以及evidence中的path、sha256、locator。检查正文中存在结论、证据文件未变化和限制非空；不自动认证语义支持或原文真实性。计算型证据的定位应包含输入、公式、单位和期间，引用型证据保留页码与引句。

最新有效范围见[当前验收范围](acceptance-current.md)，不要从累积记录中推断所有场景已完成。

## 当前记录复查

使用 `python scripts/acceptance_index.py 输入.json --output 新结果.json` 汇总指定案例。输入为 `{"cases":[{"scene":"公司研究","case":"本次样本","review":"内容复查.json","claims":"结论绑定.json"}]}`。文件路径由本次实际输出取得，不使用固定机器路径；输出文件必须尚不存在。

此检查重新读取正文和证据并比对哈希，核对内容复查与结论记录指向同一正文，列出未回答问题及部分/失败项。正文、证据变更或记录缺失时标失效或缺失；一个案例失败不阻止检查其他案例。即使绑定有效，仍不能自动认证结论正确、完成深研或通过视觉验收。新增或修订报告后重新运行，不能沿用旧汇总。


结构化证据可增加 `jsonPointer` 与 `expectedValue`，按JSON Pointer明确定位到计算输入或结果，重新验收时核对该位置存在且值一致。仅文件哈希一致不足以证明所写字段定位正确；没有结构化定位的原文仍按页码人工复查。字段匹配也不自动证明语义支持或因果。


统一清单：`python scripts/acceptance_index.py INPUT.json --output NEW.json --brief NEW.md`。每个案例指定scene、case、review及claims记录路径；重验当前正文及证据，输出最新有效案例、已回答问题、未回答问题及内容缺口。记录失效时不继续展示旧结论为有效验收；不把内容声明通过改成完整研究或视觉通过。输出文件均使用新路径，保留历史记录。
核验代码的方法哈希改变时，原记录保留为历史依据；需用原始输入及归档原文重新运行。新旧数值一致只说明此次重跑结果稳定，不能据此认证全部报表口径或将旧记录改为新方法已通过。Excel已导出的文件留存其当时输入与公式验收，后续重新生成时必须使用当前方法核验。


内容checks可增加sectionHeading，填写当前Markdown实际章节标题。绑定时核对该标题存在（代码围栏内示例标题不计）；改版删除或改名后拒绝沿用旧位置。章节定位只证明位置仍存在，理由和语义仍须重新阅读确认，不能把旧报告理由换一个哈希就当新正文验收。

章节定位检查排除代码示例中的标题；围栏关闭须使用同类符号、至少相同长度且无尾随文字。此检查只证明章节存在，不证明复查理由支持结论。

需要更细定位时，复查项可同时提供 `sectionHeading` 与 `sectionQuote`：章节须唯一，引句须实际出现在该章节正文中，其他章节及代码示例不计。引句定位不等于语义、因果或专家认可；旧记录没有该字段时仍只按其原有范围检查。

交付HTML时，在统一验收案例中提供 `htmlPath`。当前渲染器按当前Markdown及网页标题重现HTML全文，匹配则记录版本可重现；不同可能是旧正文、模板变化或其他渲染方式，须单列复查，不自动判定内容为假。网页版本匹配不等于视觉或交互通过，Markdown绑定仍单独保留。

验收CLI相对路径以各自文件为基准：清单内review/claims/htmlPath相对清单目录；复查与结论记录内reportPath、证据path相对该记录目录。绝对路径保持可用。调用不改写原记录；移动研究目录时使用相对引用并带齐所列原文和输入，不据相对路径支持宣称所有研究依赖已归档。


### 必需证据依赖

结论可用 `requiredEvidenceIds` 明确列出必需证据，证据项用 `id` 标识。例如持仓主体暴露须同时绑定发行人身份原文、持仓金额原文和复算记录。声明的依赖缺失或证据编号重复时，绑定失败；计算记录不能代替已声明的原文依赖。该检查只验证指定文件存在、哈希与结构化定位一致，不根据文件扩展名认定原文真实，也不自动证明证据充分。未声明依赖的旧记录仍按原规则核对，不据此宣称旧记录已通过依赖检查。


验收汇总逐条列出尚未声明必需证据依赖的结论，并区分声明覆盖与绑定有效。声明覆盖数量不是原文核验率、准确率或报告评分；旧记录没有声明不自动视为失败，也不能宣称已完成该检查。按研究问题确认必要原文、输入与计算后再补声明，不能为提高覆盖率机械指定现有文件。


结论绑定排除 Markdown 围栏代码块中的示例内容。只在模板代码块出现的结论不能作为报告正文结论；同样文字实际出现在正文段落或引用块时可核对。此检查不是完整 Markdown 语义解析，不认证判断质量或经济依据。


### PDF原页引句

网页原文可用 `htmlLocator: {"quote": "正文引句"}`：按UTF-8读取归档HTML，排除head、script、style、template文本，忽略空白并核对引句存在。文件哈希仍须一致。此检查不执行网页，不读取动态内容，不验证CSS可见性、来源真实性或经济解释；不能把成功匹配当作浏览器视觉验收。旧记录未设置该字段时不宣称已完成网页引句检查。

证据项可提供 `pdfLocator: {"page": 56, "quote": "原文引句"}`，page为从1开始的PDF物理页。验收需pypdf，核对页码范围及引句是否存在于指定页，忽略空白字符差异，不改数字、标点或文字；文件哈希仍必须匹配。原页读取、依赖或文字提取失败时保留核验失败，扫描件需另行人工复核。该检查只验证引句位置，不认证法律优先级、经济因果、官方来源或全部表格完整性。


### 缺口对判断的影响

结论绑定可提供gapImpacts数组，每项填写missingData、affectedQuestion、impact、nextStep。受影响问题必须在unansweredQuestions中，impact必须实际出现在报告正文，避免只在内部记录说明限制而对读者隐藏。缺失资料应说明影响及可执行的补充路径；该声明不保证资料能够取得，也不证明影响判断正确。旧记录未提供时标记not-declared，不自动声称已完成此检查。

验收索引逐项检查未回答问题是否关联缺口资料、判断影响与补取路径；缺少关联时标记`gap-impact-coverage`，不因正文已有通用风险或其他问题有路径而忽略。关联齐全仅证明登记完整，不证明补取可行或判断充分。


已保存报告快照可调用 `report_content_review.verify_snapshot_binding(BINDING_JSON_PATH)`：读取正文reportPath/reportSha256、evidence的id/path/sha256及conclusions的requiredEvidenceIds，核对实际文件版本与依赖。相对路径按绑定文件所在目录解析；重复身份、缺依赖及文件变化拒绝。此检查不验证结论文本与证据的语义关系，不能替代bind_claims的原页/结构化定位或内容复查。


跨模块评价复查时按[研究流程的场景判断](research-operating-flow.md)检查：ETF分底层/工具/交易，组合目标前置，公司分经营与价格，宏观分情景与事实，北交分公司价值与获配数学；不以指标齐全替代上述判断。数据未得的维度写未回答，不为完整外观补造结论。缺归因/DCF等专项只影响依赖它的判断。


结构化证据与验收清单拒绝NaN、Infinity以及指数溢出产生的非有限浮点数（例如1e999）；预期值也须能按有限JSON序列化。无穷大不能作为值一致或指标通过的证据。此数值边界校验不替代单位、期间、公式与经济含义复核。
