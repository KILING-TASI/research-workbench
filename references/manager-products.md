# 基金经理任职与产品关系

输入已取得的定期报告任职记录，按经理汇总已知管理产品，支持姓名查询、任职区间及对应产品历史表现。不是全职业履历搜索服务。

调用：`python scripts/manager_products.py INPUT.json --out NEW.json`。同时生成自然语言 Markdown。

输入示例：
```json
{"asOf":"2026-10-03","managerName":"某经理","products":[{"managerCompany":"某基金公司","name":"某基金","evaluationInput":{"code":"000001","asOf":"2026-10-03","managers":[{"name":"某经理","start":"2020-01-01","confirmedThrough":"2025-12-31","publishedAt":"2026-03-31","sourceUrl":"https://example.org/report.pdf","locator":"第10页"}]}}]}
```

任职业绩需要 evaluationInput 中可用历史净值及口径，详见 [基金评价](fund-evaluation.md)。无净值时保留任职关系与缺口，不生成业绩。

输出区分已披露离任、截止日在任已确认、最新在管状态待核验。旧报告无离任日期不等于今天在管。已知最早任职日期不等于职业起点；共同管理产品表现不视为单人贡献。不累加不同产品收益。

默认按公司与姓名形成候选身份，跨公司同名不合并；仅在提供明确身份编号及来源时关联。日期冲突保留并提示复核，完全重复记录拒绝。无法取得完整产品清单、最新报告或任职记录时明确列出缺口。


输出包含Markdown及HTML报告，逐产品展示任期和资料确认日期，冲突与缺项集中列示。起止日期冲突记录保留原值，但不合并进已确认管理区间，也不汇总最早任职起点。已知代码数不是独立策略数，尚未核实A/C等共享策略关系时 `strategyCount` 留空；兼容字段 `knownProductCount` 仅代表不同代码数量，见 `knownProductCountBasis`。姓名检索无结果仅说明当前输入资料无匹配，不证明其无管理产品。

报告逐项列出已知共同管理人员、交集起止日及任职来源。按单一经理姓名查询时仍保留共同管理证据。未检出交集不等于确认独立管理；历史未覆盖完整任期时明确标注实际计算区间。
